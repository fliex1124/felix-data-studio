# Felix 多平台运营基础

本文件用于统一闲鱼、淘宝、拼多多和小红书的商品准备口径。公开官网只展示服务、案例、渠道状态和合法的店铺公开链接；账号凭证、订单数据、客户信息和平台后台资料不得写入本仓库。

渠道状态不是 API 接入状态，也不代表订单已经自动同步。平台规则、可用类目、素材尺寸和发布字段可能随时间变化，每批发布前都需要在商家后台重新核验。

## 单一口径

- `data/listings.json`：11 个商品方向、服务编号、标题、素材、参考范围和渠道状态。
- `docs/service-catalog.md`：8 类标准服务和 1 个组合套餐的公开交付口径。
- `docs/platform-listing-copy.md`：平台标题、通用说明和已经定稿的逐项文案。
- `assets/listing-*-cover.html`：可重新生成的主图源模板。
- `assets/listing-*-cover-upload.*`：平台上传使用的最终图片。

服务编号用于统一官网和各平台的交付范围；商品编号用于区分同一服务在不同搜索场景下的商品入口。例如 `FDS-S08` 是“电商与社媒视觉”，对应海报详情图、店铺套装和短视频封面等多个商品方向。

## 渠道入口

官网支持通过 URL 参数保留来源并预选服务，生成需求摘要时会带上来源平台：

```text
/?source=xianyu&service=FDS-S03#brief
/?source=taobao&service=FDS-S03#brief
/?source=pinduoduo&service=FDS-S03#brief
/?source=xiaohongshu&service=FDS-S03#brief
```

只有在对应平台规则允许时，才能把公开官网地址放入店铺资料、商品内容或对话。不得通过变形文字、二维码、暗号或其他方式绕过平台的站外引流限制。来自平台的客户应在原平台完成沟通、支付、退款和售后。

## 发布流程

1. 在 `data/listings.json` 新增或更新商品，确认服务编号和商品编号唯一。
2. 核对标题、展示价对应内容、完整项目报价依据、参考周期、修改次数和不包含项。
3. 确认客户需提供的资料均要求脱敏或拥有合法使用权。
4. 用 HTML 主图模板生成最终上传图片，检查尺寸、中文、缩略图重点和文件格式。
5. 在目标平台重新核对可用类目、必填字段、图片限制、发货方式和服务费规则。
6. 发布前检查不含账号密码、API 密钥、客户数据、虚构案例、虚构销量或无法证明的效果承诺。
7. 由账号持有人在平台 App 或商家后台完成最终确认。
8. 发布后记录公开商品链接、发布时间和状态；店铺链接只有确认可公开后才加入官网。

## 平台适配重点

### 闲鱼

标题优先说明具体问题和交付方向。低展示价必须明确对应的小范围内容，不能让买家理解为完整项目价格。网页端不支持的服务类目，应使用官方 App 扫码继续发布，不使用错误类目绕过限制。

### 淘宝

优先把服务拆成可比较的规格，明确每个规格的页面数、文件数、尺寸、修改次数、源文件和交付周期。正式开店后再依据实际类目规则补充退款、开票、售后和虚拟服务交付说明。

### 拼多多

重点复核低价展示、规格差异、增项条件和交付边界，避免将咨询价或需求梳理价描述为完整交付价。活动价和平台补贴不改变服务范围及验收标准。

### 小红书

以教程、演示案例、过程拆解和获得授权的脱敏案例为主。演示数据必须明确标注，不虚构客户、业绩、销量或转化结果。是否允许店铺链接、私信链接或其他入口，以发布时平台规则为准。

## 第二阶段：订单工作台

订单汇总应放在私有后端或私有仓库，通过各平台官方开放接口、商家授权、平台通知或合规导出文件接入。公开 GitHub Pages 不存放 Cookie、Token、订单、手机号、地址或客户资料。

当某个平台没有稳定的官方订单接口时，先使用人工确认或脱敏表格导入，不采用绕过登录、模拟账号批量操作或抓取受限页面的方式。统一工作台至少需要区分：渠道订单号、商品编号、服务编号、下单时间、交付状态、约定范围、验收结果和售后状态。
