# Felix Data Studio 项目进度

最后更新：2026-08-26

本文件是项目当前进度的单一记录。以后每次迭代直接更新本文件、`data/listings.json` 和对应的网站或文档，不创建并行的旧版进度文件。GitHub 默认展示 `main` 分支的最新内容，历史提交保留用于审计和回退。

## 项目目标

建立一个面向小微企业、个体经营者和职场团队的多平台服务业务：通过闲鱼、淘宝、拼多多和小红书获客，由 Felix 官网沉淀品牌、服务与案例，后续通过私有工作台统一管理订单、任务、交付、售后和经营数据。

## 当前状态边界

- 官网仍是静态 GitHub Pages，不保存或自动发送客户填写内容。
- 官网没有已核验的店铺或商品公开链接。
- 真实案例必须获得客户授权并完成脱敏后才能展示。
- 当前公开仓库不得保存 Cookie、Token、订单、手机号、地址或其他客户资料。
- `9.90` 元展示价只对应商品文案中明确的小范围需求梳理或方向建议，不代表完整项目价格。
- `19.90` 元原价只有在存在真实价格依据且符合平台规则时才能使用，否则应删除。

## 下一步

### 当前收尾

1. 完成企业网页与活动页商品的闲鱼 App 最终发布。
2. 为 11 个闲鱼商品补充公开链接、平台商品 ID、类目、发布时间和实际状态。
3. 验证 GitHub Pages 部署结果及桌面、手机页面。
4. 在平台规则允许时，将核验后的公开店铺入口加入官网。
5. 运行一轮闲鱼验证，记录咨询问题、有效咨询、成交、退款原因、修改次数和实际工时。

### 商品标准化

1. 先为 2-3 个高频服务建立基础版、标准版和定制版。
2. 明确每档数量、范围、修改次数、源文件、参考周期、验收和售后。
3. 根据实际咨询修正标题、展示价说明和常见问题。
4. 获得授权后，把真实脱敏案例加入官网案例库。

### 平台扩展

1. 淘宝先试运行 2-3 个最标准化的商品，完成规格和售后模板。
2. 小红书同步建立教程、演示案例、过程拆解和前后对比内容。
3. 报价、履约和售后稳定后再进入拼多多。
4. 每个平台都要重新核验主体资格、类目、素材、虚拟交付和售后规则。

### 私有订单工作台

第一版先支持人工录入或合规表格导入，包含：

- 统一订单列表和渠道订单号
- 商品编号、服务编号和交付范围
- 待确认需求、制作中、待反馈、修改中、待验收、已完成等内部状态
- 客户材料清单、截止日期和逾期提醒
- 文件版本、交付记录、验收记录和售后状态
- 按平台、服务和时间汇总的经营看板

获得官方接口和商家授权后，再为淘宝、拼多多等平台增加只读订单同步、失败重试、最后同步时间和连接异常提醒。闲鱼没有稳定官方能力时保留人工确认或合规导入。

## 最终可达到的状态

完成后，Felix 可以用一份商品数据维护不同平台的标题、范围和素材；在私有工作台统一查看订单、自动创建内部任务、提醒缺少材料和截止时间、管理交付版本、生成回复草稿，并统计收入、平台费用、服务类型和交付周期。

商品首次发布、报价承诺、客户消息、退款、争议和最终交付仍保留人工确认。自动化程度取决于各平台对实际商家账号开放的官方接口，不承诺所有平台零延迟或完全无人操作。

## 更新规则

每次完成一项工作后：

1. 先更新 `data/listings.json` 中的真实商品或渠道状态。
2. 原位更新本文件的日期、完成度、已完成项和下一步。
3. 网站公开内容发生变化时同步更新 `index.html`、相关文档和素材。
4. 校验后正常提交并推送 `main`，不强制覆盖 Git 历史。
5. 不将账号凭证、平台后台信息或客户数据提交到公开仓库。
